# 3D打印机喷头裹头检测工厂模式改造设计

## 目标

本项目基于 YOLOv5 构建 3D 打印机喷头状态检测系统。代码只在 `yolov5/` 仓库内管理，外层目录用于存放数据集、参考资料、实验记录和报告素材，不纳入 Git 管理。

本次改造采用工厂模式组织项目层代码，保留 YOLOv5 核心训练、验证、推理源码的主体能力，在 `project/nozzle_inspection/` 下新增低耦合、高内聚的业务封装。最终系统应完成数据去重、数据集重划分、NG/OK 标签归并、可靠缩放增强、训练、评估、误检漏检分析和专业报告生成。

## 业务定义

检测任务采用两类目标检测策略：

- `0: NG`：所有缺陷状态统一归并为 NG，包括喷头裹头、无挤出、重污染、轻微污染、遮挡等异常状态。
- `1: OK`：所有正常状态统一归并为 OK，包括喷头清洁、正常挤出等正常状态。

业务指标以高精确率为优先目标。评估报告同时输出整体指标和 NG 类专项指标，重点关注 NG 类漏检、误检、低置信度样本和边界框质量问题。

## 数据范围

默认输入数据位于外层 `../dataset_2/`，保持原始数据只读。项目层所有清洗、重划分和增强结果输出到外层衍生目录，例如 `../outputs/datasets/nozzle_ng_ok_v1/`，避免污染原始数据集。

数据处理必须满足以下要求：

- 合并原始 `train` 与 `val` 后重新划分训练集和验证集。
- `test` 默认保留为最终测试集，不参与训练与调参。
- 图片与标签必须一一对应，缺失图片、缺失标签、空标签和非法标签需要记录到质量报告。
- 去重必须修复参考代码中的缺陷，采用文件 HASH 和感知 HASH 两级策略。
- 重划分采用分层策略，保证 NG/OK 比例在训练集和验证集中尽量稳定。

## 架构方案

新增项目层目录：

```text
project/

    reporting/
```

工厂职责：

- 数据处理工厂：创建去重、标签转换、数据划分和数据分析组件。
- 增强工厂：创建离线缩放增强、亮度对比度增强和抽检可视化组件。
- 模型工厂：生成 YOLOv5 两类数据配置、模型配置和超参数配置。
- 训练工厂：封装 YOLOv5 训练入口，统一实验命名、参数落盘和日志记录。
- 评估工厂：封装验证、阈值评估、NG 专项分析和误检漏检样本导出。
- 报告工厂：汇总数据质量、训练参数、结果指标、问题分析和结论，生成项目报告。

## 数据流

1. 从 `../dataset_2/` 读取原始 train、val、test。
2. 合并 train 与 val，生成候选训练池。
3. 对候选训练池执行 HASH 去重和感知 HASH 去重，输出重复清单。
4. 将原始多类别标签映射为 NG/OK 两类标签。
5. 按 NG/OK 分层划分 train/val，test 保持独立。
6. 对训练集执行可控离线增强，重点增强 NG 少样本和困难样本。
7. 生成 YOLOv5 所需数据目录和 `dataset.yaml`。
8. 训练工厂启动训练并记录实验配置。
9. 评估工厂输出整体指标、NG 指标、低置信度样本、误检样本和漏检样本。
10. 报告工厂生成专业项目报告。

## 标签转换

标签转换组件读取 YOLO 格式标签文件，按来源文件名前缀和原始类别编号共同决定映射关系。默认规则如下：

- `nozzle_tip_wrapped` -> NG
- `nozzle_no_extrusion` -> NG
- `nozzle_heavy_contamination` -> NG
- `nozzle_slight_contamination` -> NG
- `camera_occlusion` -> NG
- `nozzle_clean` -> OK
- `nozzle_extrusion_normal` -> OK

转换后所有标签类别只能为 `0` 或 `1`。如果出现未知前缀、非法坐标或类别越界，组件应跳过该样本并写入数据质量报告，避免脏数据进入训练。

## 去重策略

去重分两级执行：

- 精确去重：计算图片文件内容 SHA256。相同 HASH 的样本只保留一个，其余移动到重复样本清单。
- 视觉去重：计算感知 HASH，并在同一类别内比较汉明距离。相似度超过阈值时保留质量更高或路径排序更靠前的样本，其余记录为视觉近重复。

去重不直接删除原始数据，只在衍生数据集目录中排除重复样本，并输出 `deduplicate_report.csv`。

## 数据增强

增强组件必须修复缩放增强中图片和标签不同步的问题。缩放增强采用画布粘贴方案：

- 将目标区域连同标签按比例放大或缩小。
- 将缩放后的图像粘贴回固定尺寸画布。
- 同步更新 YOLO 归一化坐标。
- 裁剪越界框，过滤宽高小于阈值或面积异常的框。
- 每批增强输出抽检可视化图，便于人工确认。

增强策略默认服务于泛化能力和 NG 召回，不引入透视等不符合固定相机视角的强变换。工业场景中亮度问题通过亮度抑制、对比度增强和锐化增强单独控制。

## 训练设计

训练入口不直接要求用户手写长命令。`main.py` 根据配置调用训练工厂，训练工厂再调用 YOLOv5 原生 `train.py`。

默认训练策略：

- 模型：YOLOv5s 或当前已有改造模型配置。
- 类别数：2。
- 图片尺寸：640。
- 优化器：Adam。
- 初始学习率：`0.0001`。
- 训练轮数：先进行快速基线，再进行正式训练。
- `image_weights`：用于类别不平衡场景。
- `multi_scale`：作为实验项保留，不默认无条件扩大风险。
- `mixup`：高精确率阶段关闭或降低。
- `fl_gamma`：基线达标后再开启焦点损失实验。

所有训练实验必须记录配置文件、命令、时间、数据版本、权重路径和结果指标。

## 评估设计

评估组件输出以下内容：

- 整体 P、R、mAP50、mAP50-95。
- NG 类 P、R、mAP50、mAP50-95。
- OK 类 P、R、mAP50、mAP50-95。
- 指定置信度阈值下的混淆矩阵。
- 误检、漏检、低置信度样本清单。
- 可视化预测结果与标签对比图。

评估阈值以业务目标为导向，报告中至少比较 `conf=0.25`、`conf=0.5`、`conf=0.7` 三档阈值，说明高精确率要求下的取舍。

## 报告设计

最终报告以专业算法工程师视角组织，包含：

1. 项目背景与业务目标。
2. 数据集来源、类别归并和质量分析。
3. YOLOv5 算法原理与本项目适配方式。
4. 工厂模式架构设计。
5. 数据清洗、重划分和增强方案。
6. 实验路径、参数配置和训练过程。
7. 模型结果、阈值对比和错误样本分析。
8. 结论、风险和后续优化方向。

报告生成优先输出 Markdown，后续可按需要转换为 Word 文档。

## 错误处理

所有核心流程都应失败可诊断：

- 路径不存在时给出明确的中文错误信息。
- 图片无法读取时记录并跳过。
- 标签无法解析时记录具体文件和行号。
- 标签转换后无有效框时记录样本状态。
- 增强后无有效框时丢弃该增强样本。
- 训练命令失败时保留命令、返回码和日志路径。

## 测试与验证

实施时需要补充轻量级测试和脚本级验证：

- 标签转换测试：确认原始类别能正确映射为 NG/OK。
- 去重测试：确认完全重复样本只保留一个。
- 划分测试：确认 train/val/test 图片和标签一一对应。
- 增强测试：确认缩放增强后的框坐标合法。
- 配置测试：确认生成的 YOLO 数据配置 `nc=2` 且类别名正确。
- 语法验证：使用 `conda run -n yolo python -m py_compile` 检查新增代码。

## 非目标

本阶段不做以下工作：

- 不把外层目录初始化为 Git 仓库。
- 不删除原始数据集文件。
- 不大规模重写 YOLOv5 核心训练框架。
- 不把训练输出和大模型权重提交到 Git。
- 不直接承诺最终指标，指标以实际训练和评估结果为准。
